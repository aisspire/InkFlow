# 持续关注与来源连接（P5）

自动化负责何时检查来源；每次变化仍通过 P4 的有限运行执行。关闭浏览器不停止检查，服务关闭时不联网，重启后合并错过的时间点检查一次。没有无变化时反复生成的永久工作流。

## 使用与审阅

1. 在文章页打开“自动化”，创建持续任务。选择 HTTP、RSS/Atom 或已登记工作区内的明确项目文件。
2. 目标可以是已有文章，或每次变化新建一个未命名候选。新文最终位置通过文章页“保存文件／另存为”选择，后台不推测目录、不自动写源文件。
3. 点击“创建并启用来源审阅模板”：来源资料 → 文章与元数据准备 → 人工文章审阅 → 结束。模板不调用模型，保留原文并附入有来源、获取时间和 SHA-256 的资料区，供人工编辑核对。后续检查替换本任务此前的资料区，避免重复追加。
4. 需要模型修订或生成时，在工作流设计器中用已有“生成文章与补充问答”替换“文章与元数据准备”，并连接到人工审阅。来源是资料，不是系统指令；它不能更改流程、读取密钥或授权发布。可继续连接“确认本地输出目标 → 写入本地博客”，沿用每次人工确认与 P4 效果对账。
5. 默认固定任务创建时已启用版本；可显式选择每次派发采用最新已启用版本。每个变化项在首次派发时持久固定实际版本，重试和恢复不换版本。未校验草稿不会参与运行。
6. 点击“打开候选与待办”返回原文章审阅；确认只更新工作副本，源文件仍需显式保存。读取期间或排队后有人修改目标文章／磁盘，变化项进入“需要重新审阅”。先处理磁盘冲突，再核对当前稿、点击“按此版本重试”。旧版本按钮不能绕过 revision 校验。

首次有效读取作为首份变化证据并生成候选。暂停停止新检查和新派发，已在读取的检查仍可归档证据；当前运行单独停止。检查间隔为 60 秒至 30 天，展示 IANA 时区（UI 默认 Asia/Shanghai）和下次时间；使用固定秒数间隔，不提供 cron 或按日历时间触发。

## 来源边界

**AUTO-R01 有界读取**：HTTP/RSS 使用 GET、15 秒网络读取预算、512 KB 响应上限、至多 3 次重定向、UTF-8 文本。同一来源站点跨任务至少间隔 5 秒，限流时间持久化；发送 ETag／Last-Modified 条件头；304 或内容摘要相同不新建变化项。RSS/Atom 拒绝 DTD／实体，最多 200 条，忽略 feed 构建时间与条目顺序变化，保留原始响应和规范化条目证据。HTTP 页面保存原始文本，不执行脚本、不抓取链接或页面附属资源，不提供搜索引擎或浏览器爬取。

公开来源只允许公网 IP；“本机／内网”是对该明确 URL 的独立授权。每跳重新检查全部 DNS 地址，并连接到检查过的固定地址；HTTPS 校验证书与原主机名。重定向只能同协议、主机和端口，不能扩大能力。链路本地、保留、组播和未指定地址始终拒绝。忽略系统 HTTP 代理，不通过代理绕过地址保护。操作系统 DNS 解析可能超过网络读取预算，当前单检查线程期间其它来源顺延。

来源凭据仅支持 HTTPS Bearer 环境变量引用，名称须以 `INKFLOW_SOURCE_` 开头；UI 不接收密钥值。凭据不写入任务、证据或异常，返回内容中的本次凭据会过滤；不提供 OAuth、Cookie 或任意请求头配置。不要将密钥放在 URL 中。未经验证的供应商认证与真实公网连通性不属于本地替身证据。

项目来源限明确登记工作区内的 `.md`、`.mdx`、`.txt`、`.rst` 相对文件，最多 50 个、总计 512 KB，拒绝隐藏路径、越界、链接和非 UTF-8；缺失记录为删除证据。通过轮询检测，不依赖系统文件监听器。配置固定，调整来源或目标需暂停旧任务后创建新任务。

**AUTO-R02 自身写入隔离**：项目读取排除目标文章、自动化产生并已保存的文档及 P4 效果日志中的输出路径。自己的候选、文章保存和发布不会反向触发自身生成。被排除的输出即使后来由外部修改，仍不作为来源；需另选独立输入文件。

## 持久事实、积压和恢复

**AUTO-R03 原子游标**：`source_snapshots` 保存 URL/项目路径、获取时间、ETag、内容、摘要与引用；`automation_changes` 保存证据引用、目标基线、实际流程版本及运行；两者与游标、检查结果在同一 SQLite 事务中提交。事务提交前崩溃不推进游标；提交后崩溃从已存在变化项继续。来源变化 A→B→A 是三次可追溯变化，不把回退误当永久重复；连续相同内容只有一次。

**AUTO-R04 派发恢复**：先持久化变化项，再以 `automation-<change_id>` 为固定请求身份调用 RunManager。运行与工作队列依旧使用 P4 事务。若运行创建后、变化项记录 run_id 前崩溃，重启按请求身份找回原运行，不创建第二次运行。新文创建及其变化项关联也在一个事务内。单个任务的运行串行，同一文章的跨任务运行由 P4 单活保护；待办期间的新变化继续留证、积压，不覆盖当前候选。积压按到达顺序处理，不丢弃中间证据。

**AUTO-R05 调度与失败**：复用数据目录单执行器 OS 锁，检查有持久领取 token 与 60 秒期限。期限本身不能证明进程死亡，不允许第二个线程抢走在途检查；新服务获 OS 锁才复位旧领取。检查顺序执行，失败指数退避，最大一天；手动检查不能绕过退避。暂停／恢复有 generation 保护，任务状态展示关注、检查、重试等待、暂停、待办与积压。基础设施异常写安全日志后重试，来源异常不推进游标。

**AUTO-R06 文档与权限**：运行绑定检查开始时的文章快照与 revision，执行前复验工作副本、原路径与磁盘状态。派发冲突先保留变化项，不保存或覆盖文章；运行中冲突仍由 P3 人工动作保护。自动化接口沿用本机、同源与 JSON 写请求边界；资源只从已登记文档／工作区解析，快照详情须匹配所属任务。来源内容不获得文件、凭据或流程编辑能力。

## 接口与实现入口

| 接口 | 输入与返回 |
| --- | --- |
| `GET/POST /api/automations` | 任务列表含状态、计划、积压和待办；创建含 name、source、目标、workflow_id、version_policy、interval_seconds、timezone、enabled |
| `POST /api/automations/template` | JSON 空对象；通过正常草稿／校验／启用路径返回无模型来源审阅模板版本 |
| `GET /api/automations/{id}` | task、最近 100 个 changes（额外保留最早未处理项）、最近 50 次 checks；列表不复制文章基线 |
| `POST /api/automations/{id}/control` | generation、pause/resume/check → 更新后的任务 |
| `GET /api/automations/{id}/snapshots/{snapshot_id}` | 所属来源证据，包含受限正文和摘要 |
| `POST /api/automations/{id}/changes/{change_id}/retry` | 当前 revision → 重新排队；仅允许未派发的冲突／受阻项 |
| `GET /api/run-center?automation_id=...` | 按任务过滤正式运行；文章待办仍走原动作接口 |

实现：[来源连接](../src/inkflow/automation/sources.py)、[调度和持久积压](../src/inkflow/automation/service.py)、[API](../src/inkflow/automation/api.py)、[自动化中心](../frontend/src/AutomationCenter.tsx)、[验收测试](../tests/test_automation.py)。来源资料节点使用原定义编译、诊断、模拟与 P4 检查点；模拟使用标识为模拟的资料，不联网。

## 迁移、限制与下一阶段

启动幂等新增 `automations`、`source_snapshots`、`automation_changes`、`automation_checks`、`automation_source_limits`，保留已有草稿、工作流、历史、运行与动作。没有替换包管理器、依赖或 lockfile。升级前停服并备份整个数据目录、配置、文章与输出；源码指纹变化的在途 P4 运行仍拒绝盲恢复，升级前应完成／停止，或使用匹配旧代码核对后结束。旧用户流程需从原版本创建草稿、重新校验启用以采用当前实现；旧版本与历史不改写。回退先暂停自动化、保留新稿与证据，再恢复匹配的升级前数据库；不得让新旧代码交替写同库，回退数据库不撤销已输出文件。

不提供无人值守采用、保存或发布，不支持任意代码连接器、cron、多机调度、目录递归扫描、来源删除管理或历史自动压缩。证据、检查和积压长期保留，规模很大时需规划归档；任务列表当前为本机小规模实现。文件系统与 SQLite 仍非统一事务，采用和输出继承 [P4 剩余故障窗口](durable-execution.md)。[P6 AI 编排与修复](ai-orchestration.md) 已实施；修复固定原来源快照且不自动修改持续任务的流程选择。

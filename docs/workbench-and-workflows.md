# 以文章为中心的工作台与工作流

## 工作台规则

当前前端采用文章、工作流、任务、设置四区页面。入口归属、URL 状态、切页会话、统一正文审阅和能力边界见 [应用导航与文章审阅](frontend-navigation.md)；以下文档和版本保护继续有效。

- **WB-R01 文档身份**：随机稳定 `document_id` 与宿主规范化绝对路径唯一映射；同一文件经独立入口、工作区或重叠目录共用工作副本和历史，不同位置同名文件独立。精确文件登记不授权父目录。每次文件读写重新校验后缀、普通文件、符号链接及位置边界；不支持工作区根以下的隐藏文件／目录、符号链接、非 UTF-8 或超过 2 MB 的文章；显式登记的工作区根本身可位于隐藏父目录，保持旧授权语义。原文件失联保留草稿和 ID，明确提示，不按内容自动关联。
- **WB-R02 文件组织**：侧栏长期保留所有打开过的文章，按规范化真实路径分层并压缩单分支目录，跨盘或路径根分别分组；未命名稿单列。目录仅从这些文件推导，不扫描其它磁盘文件。统一按文件名／路径搜索，显示当前文章、草稿、运行与已发现的失联状态；点击正文顶部文件名查看、复制完整路径。“从侧栏移除”只移除浏览器入口，不删除文件、草稿、历史或运行；最近文章按工作副本更新时间排列，可重新加入。切换替代文章失败则保留当前入口。首次升级纳入已有登记文档，之后显式移除不因刷新自动返回。
- **WB-R03 会话保持**：切换文章先持久化草稿；CodeMirror 按 document_id 缓存 EditorState、光标、选择、滚动、撤销／重做，预览、辅助页签与选中问题按文档保留。默认目录修改不重挂载正文。约 650ms 自动持久化草稿，未完成时离页提示；刷新恢复文档 ID、路径树、默认目录、草稿与运行，撤销栈只限当前页面。保存失败暂停自动重试并保留输入；revision 冲突可“保留本地稿并读取最新”，先创建独立草稿再读服务器最新副本，避免覆盖另一标签页。
- **WB-R04 运行上下文**：运行固定输入文本、revision、摘要和目标 document_id，页面选择不改变它。A 文章存在运行／人工待办时可打开、编辑任意位置的 B，返回 A 可继续原待办。历史选择与节点按文档／运行保存。候选只修改对应工作副本，历史运行只读；旧无关联历史不猜测归属。
- **WB-R05 布局**：保持浅色主题、字体、正文排版、MUI、差异审阅和窄屏 Drawer；文件与辅助窗格可收起，分隔条支持拖动／键盘。文件树目录支持方向键展开收起，表单有标签，路径、保存、待办与错误操作在窄屏可达。
- **WB-R06 默认保存目录**：界面只设置普通绝对目录，作为未命名稿首次保存建议位置，按浏览器持久保存；初始沿用旧工作区选择或启动目录。修改目录不迁移文章、草稿或运行，不登记工作区、不扫描文件、不写应用配置。目录不存在时提示重新选择并保留草稿。旧多工作区服务继续用于来源采集、筛选和兼容客户端；旧 `/editor/workspace` 仍有全局切换与活跃运行阻止规则，`X-InkFlow-Workspace` 仍在锁内校验，过期返回 409。文章主界面不再调用工作区登记、文件发现或切换接口，旧路径会话迁移除外。目录浏览只填字段，确认后生效。
- **WB-R07 运行读取边界**：新运行详情、动作、SSE、候选与产物携带 `document_id` 查询参数（也支持 `X-InkFlow-Document`），在运行锁内校验已登记资源与运行所属文档，错误目标返回 404。SSE 每批与逐条发送前复查。未提供新身份的旧调用继续核对当前工作区，不因新接口移除旧校验。新文档历史按 ID 查询，摘要覆盖已登记文档；旧历史默认仍限旧全局工作区，`unlinked=true` 提供无归属只读历史。
- **WB-R08 文件权限**：POSIX 数据目录 0700、数据库及日志／密钥 0600；Windows 保持当前用户 DACL。普通文章原子替换保留原模式，新文件遵循 umask，不修改进程 umask。所有本机接口继续使用同源、Host、请求体大小与密钥边界。
- **WB-R09 新建与保存**：新建即有 ID 和应用数据目录中的持久草稿，不创建磁盘空文件。首次保存预填默认保存目录，成功保留 ID 并在路径树定位；另存为要求不存在的目标，创建新 ID、记录来源并切换后续编辑对象，原文档入口保留，默认使用当前文章目录。原子独占发布拒绝同名竞争，不覆盖已有或失联登记位置。显式保存保持 revision、磁盘指纹和原子写入；外部修改拒绝覆盖，读取磁盘前保存草稿历史。自动持久化、候选采用、恢复历史只表示“草稿已保留 · 未写回文件”；文件写入成功才显示“已保存到文件”。“草稿保存中”“保存文件中”“失败／冲突”单独反馈，工作流状态另列。保存标志独立于文本相等判断；候选采用或历史恢复即使正文与磁盘相同，也需显式保存后清除未写回标记。
- **WB-R10 增量迁移**：旧工作区＋相对路径映射到 document_id，原 editor_docs / editor_versions 不改写；新副本／版本表承接编辑。多个旧键指向同一位置时合并身份，按旧键顺序选首稿，差异稿完整保留为 migration_conflict 并提示人工核对，冲突版本不受最近 200 版展示窗口限制。运行与候选基线只增补 document_id，旧路径、输入和版本 ID 保留。别名标记使重复迁移不重置新草稿；无法证明路径边界的旧记录保留原样。升级前备份数据目录；回退旧代码只能读迁移前旧表，新草稿须先保存／导出，不支持新旧应用交替写入同一数据库。

- **WB-R11 失联重新关联**：打开或刷新发现失联时保留文档和草稿。用户可另存为，或明确输入移动后原文件的完整路径重新关联；仅允许原位置不存在、目标未登记且内容指纹匹配原磁盘基线，继续校验 revision、格式、编码、普通文件和链接。成功保留 ID、草稿、历史与运行，不移动文件或合并身份；目标内容不同则独立打开核对或另存为。

- **WB-R12 最近记录与草稿清理**：在“最近文章与移除的草稿”中，已有文件可以逐条“清除最近记录”，仅隐藏本浏览器入口，刷新保持隐藏；文件、未写回草稿、版本和运行保留，显式打开文件或从任务进入后恢复入口。未命名草稿提供独立“删除草稿”，确认后永久删除工作副本及全部编辑版本，刷新不再出现。删除携带列表中的 revision，服务端在运行锁、文档锁和事务中复查；版本过期、已有文件位置（含失联）、活跃运行／待办、持续关注任务引用或待处理来源候选均拒绝，失败保留条目。保留文档身份及已有运行记录、输入快照供审计；此操作不删除磁盘文件，也不清除所有历史内容。

  持续关注引用的草稿可先保存到文件，再清除最近记录；文档 ID 与任务引用继续有效。暂停持续关注不会解除文档引用。

## 工作流定义与运行

提示词、草稿保存／启用、固定样例、节点诊断、输出配置与版本迁移详见 [P2 当前行为](workflow-assets.md)。新运行固定启用版本包，人工续跑不读取后来修改的提示词和参数。

| ID | 名称 | 实际流程 |
| --- | --- | --- |
| `full-check` | 全文检查 | 固定输入 → 模型检查 → 定位建议 → 人工处理 → 结束本轮 |
| `redaction-only` | 仅脱敏 | 固定原文 → 风险检查 → 人工审核 → 改写 → 差异确认 → 复查 → 明确结束；不生成或发布 |
| `reviewed-publishing` | 文章处理与审阅 | 脱敏审核、改写与复查、生成与追问、最终审阅、明确输出、报告与审计 |

**WF-R01 统一运行**：注册表提供真实工厂、图描述和人工动作校验；Web 和 CLI 使用同一注册表。每次启动创建独立 graph/runtime、输入与配置快照、事件、执行、图结构与产物。全文检查不再维护独立检查任务。

**WF-R02 文章单活**：新 Web 运行必须关联已登记 document_id（包括未命名文档）、revision 与实际文本；服务端校验身份、版本并持久化未保存输入。RunManager 锁与 以 document_id 为键的 SQLite `article_active` 唯一主键共同防止同文章并发创建。运行、等待人工和停止中均占用名额；终态释放。不同文章允许同时创建，线程池最多四个执行线程，人工等待不占用线程。超出线程数时任务等待执行，仍占用文章名额。

**WF-R03 轮次**：全文检查生成建议后进入 waiting，零建议也等待用户结束。不强制处理全部建议。“结束本轮”推进终点并释放名额；重新检查先结束当前检查，再基于当前工作副本创建新实例，保存 `rerun_of` 和反馈。失败、停止、中断均可基于当前稿件新建，旧记录可回看。全文检查上限 24,000 Unicode 字符，必须配置启用的模型和密钥，不截断。

**WF-R04 标注与审核**：运行持有建议和处理事实，工作副本服务负责版本与保存。全文检查支持采用、忽略、拒绝反馈及已处理列表；结构建议允许无局部位置。标注记录文章、run、步骤、版本、问题 ID、原文、UTF-16 范围和状态；snapshot_start / snapshot_end 保留检查快照内原始位置，start / end 是工作副本投影。服务端与 CodeMirror 映射未受影响范围；修改命中或重复片段映射有歧义时永久标记待复查。失效结果不能采用或错误高亮，撤销回原文不自动复活。点击问题与正文标记双向选择。历史提供检查快照只读查看。

**WF-R05 脱敏稿推进**：文章工作台预处理保留输入原文，文章处理 CLI 保留旧清洗规则；仅脱敏始终保留固定原文。检测保存实际 checked_text，定位先用行区间内唯一片段，再用全篇唯一片段；不能可靠定位时不给高亮。人工审核后生成 candidate_text，主编辑器继续显示当前稿；接受差异时由服务端校验文章、revision 和确认基线，事务保存 before_workflow_apply / workflow_apply，立即安装已确认脱敏稿，再基于该稿复查。候选确认前发生新编辑则拒绝覆盖，界面可重新对比并明确确认替换，或返回重新改写。前后版本可恢复，原文件仍需显式保存。

**WF-R06 其余分支与边界**：文章生成、最多三次人工追问、降级占位、文章属性编辑、最终审阅、报告、审计与显式博客输出保留。其它生成稿仍经文稿桥接显式对比载入，载入后可提交主编辑稿回工作流；未提交的新改动不能确认输出。停止在节点边界生效，进行中的模型请求完成或超时后停止。request_id 幂等、pending_id 校验、SSE 游标补发、密钥隔离与磁盘指纹保护保留。

**WF-R07 兼容**：旧 `editor_tasks` 和旧建议字段保留，不批量转换或删除；旧独立检查的 running 草稿在读取时显示 interrupted；新全文检查运行以 runs / events / actions 保存。旧无 workflow_id 记录读取时使用默认文章处理定义；旧无 editor_source 记录单独只读展示。新 Web 上传/粘贴无归属创建路径关闭；CLI 仍支持独立文件输入。旧无恢复协议运行重启标记 interrupted；P4 正式运行保留名额并恢复原待办或固定执行位置，未知效果先对账，详见 [恢复规则](durable-execution.md)。

**WF-R08 可视化差异**：脱敏差异确认、候选冲突与生成稿载入共用彩色文本对比。新差异待办到达时进入“节点详情”并展开辅助窗格，避免被旧风险卡片遮挡；后续轮询不重复切页。红底和减号表示删除，绿底和加号表示新增，行内深色标记具体修改；显示原/新行号、改动处数和增删行统计，可跳转上一处/下一处。默认保留改动附近三行上下文，未改内容可展开，也可查看完整上下文；长段按每次 100 行继续显示，不缩短实际候选。窄栏逐行展示，可放大后并排查看；窄窗口自动逐行。

对比以完整前后文本为准：脱敏取本轮检测快照与候选，冲突取当前稿固定快照与候选，生成稿取预览请求固定稿与完整结果。保留 BOM、空行、CRLF/LF 和末行换行差异，不依赖旧 unified diff 或其截断结果。大段重写超出细分预算时按整段增删展示并提示，仍可逐步查看全部内容。相同正文明确显示无改动；内容只作为文字渲染，不执行 HTML/MDX。可视化组件只读；接受、重试、冲突确认、revision、候选 ID、版本历史与显式磁盘保存继续遵循 WF-R05 / WF-R06。

## 接口与命令行摘要

路径均加 `/api`，保留同源与本机边界。

| 接口 | 关键请求 | 返回与职责 |
| --- | --- | --- |
| `GET /documents`、`POST /documents` | 无 | 已登记文档摘要；创建有 ID 的未命名草稿 |
| `POST /documents/open`、`POST /documents/pick-file` | 完整 path／原生选择 | 精确文件登记与完整工作副本；不登记父目录 |
| `GET /documents/{id}`、`GET /documents/{id}/versions` | document_id | 工作副本、位置、失联／冲突提示；最近版本与迁移冲突稿 |
| `DELETE /documents/{id}` | revision | 删除未命名工作副本与编辑版本，返回 `{deleted: document_id}`；冲突 409，不存在 404；保留已有运行审计 |
| `POST /documents/{id}/operation` | revision、text、action、version、stale_ids | edit/save/restore/reload；显式保存才写文件 |
| `POST /documents/{id}/save-as` | revision、text、完整目标 path | 首次保存保留 ID；已有文件文档另存为新 ID，拒绝重名 |
| `POST /local-directory` | 完整目录 path | 校验并返回规范化目录，不登记、扫描或保存偏好 |
| `POST /documents/{id}/relocate` | revision、text、移动后的完整 path | 显式恢复失联位置，保留 ID、草稿、历史与运行 |
| `GET /workspaces`、`POST /workspaces` | 无／完整目录 path | 来源采集与旧客户端使用的持久目录清单／ID 与根路径 |
| `GET /workspaces/{id}/files`、`POST /workspaces/{id}/open` | workspace_id、相对 path | 完整文件与目录、修改时间及草稿元数据／统一文档 |
| `GET /document-runs` | 无 | 按 document_id 的最新／活跃运行摘要 |
| `GET /editor/files` | 无 | 工作区与全量可打开文章路径 |
| `POST /local-picker` | purpose（article/workspace/blog_repository/blog_content/review/report）、可选 initial_path / repo_path | 打开本机系统窗口；返回 `{path}`，取消为 null；文章返回工作区相对路径，内容目录返回仓库相对路径，其它目录返回绝对路径；不保存配置或切换工作区 |
| `POST /editor/workspace` | path | 无活跃运行时切换当前服务工作区；返回 `{root,files}`；失败回退，客户端成功后刷新恢复会话 |
| `GET /editor/document` | path | 当前持久化工作副本、workspace、revision、磁盘基线 |
| `POST /editor/operation` | path、revision、text、action、stale_ids | edit/save/restore/reload；旧 check 兼容入口创建正式 full-check 运行；旧直接建议写操作拒绝 |
| `GET /editor/versions` | path | 最近 200 个版本；恢复不写磁盘 |
| `GET /workflows`、`GET /workflows/{id}` | 工作流 ID | 注册定义与真实图；`GET /workflow` 保留默认图兼容入口 |
| `POST /runs` | request_id、workflow_id、raw_text、editor_source `{document_id,revision}`（旧 path 适配保留）、no_publish、可选 rerun_of / feedback | 文章绑定的新运行与输入快照；校验单活和版本 |
| `GET /article-runs` | 无 | 当前工作区各文章最新/活跃运行摘要，供非当前文章状态轮询 |
| `GET /runs` | document_id；旧 path 或 workspace=true；可选 unlinked=true；limit、offset | 当前文章历史或未关联旧历史 |
| `GET /runs/{id}` | run ID、document_id | 运行、待办、实际图、最近 200 事件、annotations 与 annotation_snapshot |
| `POST /runs/{id}/actions` | request_id、pending_id、action、payload | 全文检查 accept/ignore/reject 带 suggestion_id 与 editor `{document_id,revision,text,stale_ids}`；finish_check 结束；脱敏 accept 带 editor 与必要的 confirm_conflict；其余审核保持 |
| `POST /runs/{id}/document-preview`、`document-apply` | document_id、revision、text、result_id、confirm_conflict | 生成稿显式对比与载入；终态或无归属历史不能载入 |
| `GET /runs/{id}/events` | document_id、after / Last-Event-ID | 有序 run_event / end，客户端重取事实 |

CLI 保留 `--config`、`--input`、`--no-publish`；`--workflow` 可选三个内置流程。默认仍为 reviewed-publishing，全文检查终端可查看建议并结束本轮，结果展示使用通用完成/停止/失败状态及建议数量，不依赖文章审核专有字段；失败退出码为 1。所有 Python 操作先激活 openai_agents。

## 验证与范围

## P3 定义驱动工作流

“工作流”可创建或复制独立流程、组合注册节点并编辑输入／连接；版本包格式 2 先校验和编译再显式启用，原内置格式 1 保持兼容。新增用户流程即时进入选择器，运行固定自己的图、节点和配置修订。发布已有文章模板无需生成模型；目标确认与写入共用固定预览，输出仅表示本地文件成功。流程模拟不占文档名额、不采用工作副本、不写文件。顶部“运行记录”跨已登记文档查询，详情／动作仍校验资源归属。完整交互、API、迁移和限制见 [P3 当前行为](workflow-definitions.md)。

# 以文章为中心的工作台与工作流

## 工作台规则

- **WB-R01 文章身份**：工作区绝对路径与规范化文章相对路径共同标识文章。磁盘原文件、当前工作副本、运行输入快照、未确认候选稿、已确认版本分别保存。打开和编辑不依赖模型。
- **WB-R02 已打开文章**：左侧仅显示已打开文章，并保留真实目录层级；“打开文章”搜索整个工作区，也可通过“浏览文件…”调用后端所在电脑的系统文件选择窗口，直接打开原文。只接受当前工作区内的 UTF-8 Markdown／MDX，工作区外文章需先切换工作区；取消不改变当前文章。重复打开选中已有条目。关闭视图不停止运行、不删除持久化草稿。浏览器按工作区保存已打开列表和当前文章，SQLite 保存草稿。
- **WB-R03 会话保持**：切换文章保存草稿；CodeMirror 按文章缓存 EditorState，保留光标、选择、滚动与撤销/重做。预览模式、辅助页签、选中问题按文章保留。刷新恢复草稿和运行，但不恢复撤销栈。编辑后约 650ms 持久化本地草稿，尚未持久化时离页提示；只有“保存”写回原文件。
- **WB-R04 上下文**：正文、建议、人工待办、真实流程图、节点详情与运行历史均属于当前文章。历史选择按文章保存，返回当前运行可继续待办；旧无文章关联历史通过单独入口查看，不推断归属。历史结果不能修改当前正文。
- **WB-R05 布局**：复用浅色主题、窄屏 Drawer 和纵向辅助窗格；面板可收起和拖动/键盘调整。收起辅助区仍可查看状态、停止、结束检查或进入待办。目录折叠、原生按钮键盘操作、搜索和页签键盘导航可用。
- **WB-R06 工作区与目录选择**：左侧工作区旁、文章选择弹窗和首页空态可进入工作区选择；“浏览…”填入系统选择的文件夹，也可手输。点击“切换工作区”先持久化当前草稿，服务端在没有活跃运行时切换全局工作区，随后刷新页面按目标工作区恢复会话；运行中、等待人工和停止中均阻止切换。选择仅本次服务启动有效，重启仍使用启动参数或配置目录。失败保留原工作区。页面请求携带 URL 编码的 `X-InkFlow-Workspace`，服务端在运行锁内校验，旧页面的文章读写与动作返回 409，避免同名文章串写；无此标识的旧客户端保留兼容。设置的四个目录字段也支持系统选择，博客内容结果必须是仓库内相对路径；选择只填表，点击“保存设置”生效。系统窗口同时最多一个，取消不改值；无 Tk／桌面或超时明确提示，继续支持文章搜索与手输目录。
- **WB-R07 运行读取边界**：运行详情、事件、产物及修改入口均核对 `editor_source.workspace` 与当前服务工作区。无请求头或携带当前工作区头也不能读取其它工作区运行，返回 404；过期工作区头返回 409。已有 SSE 在读取事件及逐条发送前再次校验，切换后结束流。历史列表默认只查当前工作区，旧无归属历史仍通过 `unlinked=true` 单独只读查看；切回原工作区可重新读取其历史。
- **WB-R08 文件权限**：POSIX 应用数据目录 0700、数据库及 WAL/SHM/journal 和密钥 0600，启动修复旧数据库权限。Windows 数据目录和密钥显式使用当前用户 DACL，移除其它账户授权和宽泛继承，密钥写入前设权失败即终止。普通 POSIX 文章原子替换保留目标模式，新建按 0666 与 umask 创建；不修改进程级 umask。

## 工作流定义与运行

| ID | 名称 | 实际流程 |
| --- | --- | --- |
| `full-check` | 全文检查 | 固定输入 → 模型检查 → 定位建议 → 人工处理 → 结束本轮 |
| `reviewed-publishing` | 文章处理与审阅 | 脱敏审核、改写与复查、生成与追问、最终审阅、明确输出、报告与审计 |

**WF-R01 统一运行**：注册表提供真实工厂、图描述和人工动作校验；Web 和 CLI 使用同一注册表。每次启动创建独立 graph/runtime、输入与配置快照、事件、执行、图结构与产物。全文检查不再维护独立检查任务。

**WF-R02 文章单活**：新 Web 运行必须关联当前工作区文章、revision 与实际文本；服务端规范化路径、校验版本并持久化未保存输入。RunManager 锁与 SQLite `article_active` 唯一主键共同防止同文章并发创建。运行、等待人工和停止中均占用名额；终态释放。不同文章允许同时创建，线程池最多四个执行线程，人工等待不占用线程。超出线程数时任务等待执行，仍占用文章名额。

**WF-R03 轮次**：全文检查生成建议后进入 waiting，零建议也等待用户结束。不强制处理全部建议。“结束本轮”推进终点并释放名额；重新检查先结束当前检查，再基于当前工作副本创建新实例，保存 `rerun_of` 和反馈。失败、停止、中断均可基于当前稿件新建，旧记录可回看。全文检查上限 24,000 Unicode 字符，必须配置启用的模型和密钥，不截断。

**WF-R04 标注与审核**：运行持有建议和处理事实，工作副本服务负责版本与保存。全文检查支持采用、忽略、拒绝反馈及已处理列表；结构建议允许无局部位置。标注记录文章、run、步骤、版本、问题 ID、原文、UTF-16 范围和状态；snapshot_start / snapshot_end 保留检查快照内原始位置，start / end 是工作副本投影。服务端与 CodeMirror 映射未受影响范围；修改命中或重复片段映射有歧义时永久标记待复查。失效结果不能采用或错误高亮，撤销回原文不自动复活。点击问题与正文标记双向选择。历史提供检查快照只读查看。

**WF-R05 脱敏稿推进**：文章工作台预处理保留输入原文，CLI 保留旧清洗规则。检测保存实际 checked_text，定位先用行区间内唯一片段，再用全篇唯一片段；不能可靠定位时不给高亮。人工审核后生成 candidate_text，主编辑器继续显示当前稿；接受差异时由服务端校验文章、revision 和确认基线，事务保存 before_workflow_apply / workflow_apply，立即安装已确认脱敏稿，再基于该稿复查。候选确认前发生新编辑则拒绝覆盖，界面可重新对比并明确确认替换，或返回重新改写。前后版本可恢复，原文件仍需显式保存。

**WF-R06 其余分支与边界**：文章生成、最多三次人工追问、降级占位、文章属性编辑、最终审阅、报告、审计与显式博客输出保留。其它生成稿仍经文稿桥接显式对比载入，载入后可提交主编辑稿回工作流；未提交的新改动不能确认输出。停止在节点边界生效，进行中的模型请求完成或超时后停止。request_id 幂等、pending_id 校验、SSE 游标补发、密钥隔离与磁盘指纹保护保留。

**WF-R07 兼容**：旧 `editor_tasks` 和旧建议字段保留，不批量转换或删除；旧独立检查的 running 草稿在读取时显示 interrupted；新全文检查运行以 runs / events / actions 保存。旧无 workflow_id 记录读取时使用默认文章处理定义；旧无 editor_source 记录单独只读展示。新 Web 上传/粘贴无归属创建路径关闭；CLI 仍支持独立文件输入。重启将未完成运行标记 interrupted 并清理名额，不恢复执行，不引入跨重启续跑或通用调度。

**WF-R08 可视化差异**：脱敏差异确认、候选冲突与生成稿载入共用彩色文本对比。新差异待办到达时进入“节点详情”并展开辅助窗格，避免被旧风险卡片遮挡；后续轮询不重复切页。红底和减号表示删除，绿底和加号表示新增，行内深色标记具体修改；显示原/新行号、改动处数和增删行统计，可跳转上一处/下一处。默认保留改动附近三行上下文，未改内容可展开，也可查看完整上下文；长段按每次 100 行继续显示，不缩短实际候选。窄栏逐行展示，可放大后并排查看；窄窗口自动逐行。

对比以完整前后文本为准：脱敏取本轮检测快照与候选，冲突取当前稿固定快照与候选，生成稿取预览请求固定稿与完整结果。保留 BOM、空行、CRLF/LF 和末行换行差异，不依赖旧 unified diff 或其截断结果。大段重写超出细分预算时按整段增删展示并提示，仍可逐步查看全部内容。相同正文明确显示无改动；内容只作为文字渲染，不执行 HTML/MDX。可视化组件只读；接受、重试、冲突确认、revision、候选 ID、版本历史与显式磁盘保存继续遵循 WF-R05 / WF-R06。

## 接口与命令行摘要

路径均加 `/api`，保留同源与本机边界。

| 接口 | 关键请求 | 返回与职责 |
| --- | --- | --- |
| `GET /editor/files` | 无 | 工作区与全量可打开文章路径 |
| `POST /local-picker` | purpose（article/workspace/blog_repository/blog_content/review/report）、可选 initial_path / repo_path | 打开本机系统窗口；返回 `{path}`，取消为 null；文章返回工作区相对路径，内容目录返回仓库相对路径，其它目录返回绝对路径；不保存配置或切换工作区 |
| `POST /editor/workspace` | path | 无活跃运行时切换当前服务工作区；返回 `{root,files}`；失败回退，客户端成功后刷新恢复会话 |
| `GET /editor/document` | path | 当前持久化工作副本、workspace、revision、磁盘基线 |
| `POST /editor/operation` | path、revision、text、action、stale_ids | edit/save/restore/reload；旧 check 兼容入口创建正式 full-check 运行；旧直接建议写操作拒绝 |
| `GET /editor/versions` | path | 最近 200 个版本；恢复不写磁盘 |
| `GET /workflows`、`GET /workflows/{id}` | 工作流 ID | 注册定义与真实图；`GET /workflow` 保留默认图兼容入口 |
| `POST /runs` | request_id、workflow_id、raw_text、editor_source `{path,revision}`、no_publish、可选 rerun_of / feedback | 文章绑定的新运行与输入快照；校验单活和版本 |
| `GET /article-runs` | 无 | 当前工作区各文章最新/活跃运行摘要，供非当前文章状态轮询 |
| `GET /runs` | path 或 workspace=true；可选 unlinked=true；limit、offset | 当前文章历史或未关联旧历史 |
| `GET /runs/{id}` | run ID | 运行、待办、实际图、最近 200 事件、annotations 与 annotation_snapshot |
| `POST /runs/{id}/actions` | request_id、pending_id、action、payload | 全文检查 accept/ignore/reject 带 suggestion_id 与 editor `{path,revision,text,stale_ids}`；finish_check 结束；脱敏 accept 带 editor 与必要的 confirm_conflict；其余审核保持 |
| `POST /runs/{id}/document-preview`、`document-apply` | path、revision、text、result_id、confirm_conflict | 生成稿显式对比与载入；终态或无归属历史不能载入 |
| `GET /runs/{id}/events` | after / Last-Event-ID | 有序 run_event / end，客户端重取事实 |

CLI 保留 `--config`、`--input`、`--no-publish`；`--workflow` 可选两种注册流程。默认仍为 reviewed-publishing，全文检查终端可查看建议并结束本轮，结果展示使用通用完成/停止/失败状态及建议数量，不依赖文章审核专有字段；失败退出码为 1。所有 Python 操作先激活 openai_agents。

## 验证与范围

按现有包管理器、lockfile 与已安装工具验证。激活 openai_agents、设置 `PYTHONPATH=src` 后运行 `python -m unittest discover -s tests -v`，可重现 CLI 完成/停止/失败、工作区隔离与已有 SSE、原子写入失败清理、POSIX 权限与 Windows 真实 DACL 回归；操作系统专有检查在另一平台跳过，不新增测试依赖。临时隔离脚本另覆盖文章绑定、并发单活、跨文章运行、正式检查生命周期、UTF-16、历史、候选冲突与自动安装、磁盘保护、SSE 与重启；浏览器覆盖文章切换、撤销/重做、刷新、关闭重开和响应式。实际结果与未验证项记录于根目录 implementation-notes.md。

不扩展文件监听、定时任务、可视化编排、任意插件或跨重启执行。模型质量与真实服务连通性不由替身验证证明。

# 应用导航与文章审阅

此文记录当前前端信息架构，沿用 P1–P6 的后端、权限、工作副本、候选、版本和输出协议。

## 页面与归属

全局仅有一组导航：文章、工作流、任务、设置。工作流、运行记录、持续关注和设置均为页面内容，不以全屏 Dialog 导航。

| 页面 | 职责 |
| --- | --- |
| 文章 | 打开历史的路径树、未命名草稿、默认保存目录、主正文编辑器、属性、建议与候选审阅、本文运行 |
| 工作流 | 流程选择与创建／复制；设计、测试、版本；AI 创建和关联诊断修复 |
| 任务 | 运行记录和持续关注两个视图；完整运行详情、来源变化、证据与核验 |
| 设置 | 应用默认模型与目录、凭据、共享发布配置；说明与流程版本配置、浏览器工作区偏好的区别 |

**NAV-R01 单一导航**：文件区按真实路径分组保留打开过的文章，压缩单分支目录，不扫描目录；未命名稿独立分组。顶部统一搜索文件名或路径，目录可用方向键展开收起，当前文章高亮。显式“从侧栏移除”只移除浏览器入口，文件、草稿、历史与运行均保留，可从最近文章重新加入；切换到替代文章失败时不移除当前入口。文章顶栏保留当前文章、保存状态、保存和次要操作菜单。历史为侧栏，文件位置可就地查看和复制，文件选择弹窗只处理单个文件。

**NAV-R05 默认保存目录**：文件区底部设置普通绝对目录，仅作为未命名稿首次保存的位置。设置按浏览器保存，首次升级沿用旧工作区选择或启动目录；校验目录时不登记工作区或扫描文件。修改目录不移动文章、改变运行、重建编辑器或写入应用全局配置。新建先持久保留未命名稿，显式保存后才产生磁盘文件；目录失效时提示重新选择，保留稿件。首次保存保留 ID 并进入对应路径；另存为创建新 ID，原文档入口保留。

**NAV-R06 失联恢复**：打开或刷新发现原文件失联时保留文档和草稿，可另存为或手输移动后路径重新关联。重新关联仅接受原位置不存在、目标未登记且内容指纹等于原磁盘基线的文件，保留 ID、历史、草稿与运行，不移动文件或合并已有文档。内容不同需独立打开核对或另存为。

**NAV-R07 清理**：“最近文章与移除的草稿”中的已有文件可清除本浏览器最近记录，保留文件、草稿和历史；重新打开会恢复入口。未命名草稿有独立删除按钮，确认框说明正文与编辑版本永久删除、已有运行及输入快照保留，默认聚焦取消。失败在确认框显示原因并保留条目；版本变化、运行／待办或持续关注引用需先处理。空列表显示空状态，清理按钮支持键盘和窄屏触控。完整删除边界见 [WB-R12](workbench-and-workflows.md#工作台规则)。

**NAV-R08 紧凑侧栏**：路径树和最近列表采用单行文件项，桌面 32px、窄屏／触屏 40px；当前文章高亮，操作按钮保留。完整路径、保存状态、失联原因与工作流状态通过悬浮、键盘聚焦或触屏长按查看，不在文件名下方重复展示。长目录名省略显示且不换行；默认保存目录收为单行设置入口，完整目录放入悬浮信息。

**NAV-R02 URL**：浏览器 History API 保存 `page`、工作流 `workflow`／`stage`、任务 `tab`、运行 `run`／`runDocument`、记录范围 `recordScope`、持续任务 `task`、文章 `document`／`articleRun`、AI `ai`／`step`／`proposal`。文章运行与任务选中运行分开，浏览任务不会改变文章会话。刷新、前进和后退读取同一状态；接口仍校验资源归属，URL 本身不授予权限。非法页面／视图回退到默认值，失效资源显示原服务错误。旧版未关联历史仍可在任务的记录范围中查看，不能确认没有文章归属的候选。

**NAV-R03 会话**：文章和流程组件切页隐藏而不卸载。文章正文、选区、滚动、撤销重做和侧栏路径树继续沿用原会话机制；流程定义、选中节点、样例与测试结果在设计／测试／版本切换时保留。跨刷新恢复服务端已持久化的文章工作副本、保存的流程草稿、测试记录和浏览器路径树；显式移除的文章不会自动重新加入，URL 或用户打开可重新加入。撤销栈和未保存流程输入不跨刷新。离开浏览器前对未持久化输入继续提示。

**NAV-R04 来源返回**：持续关注可进入原文档审阅；运行详情的文章确认入口携带原 document_id 与 run_id。文章“返回来源页面”恢复本次任务位置。AI 修复从具体失败尝试进入工作流页面，返回恢复来源查询参数；AI 来源存于本浏览器会话，不作为服务端授权依据。

## 编辑与候选

**REVIEW-R01 文章权威**：主编辑器是正文修改入口。当前工作副本、运行候选和已确认输出版本分别标记；候选比较只读。旧内置发布流程的候选通过既有 `WorkflowDocumentBridge` 显式比较、采用，修改后显式提交编辑稿生成新的审阅版本。旧弹窗正文编辑器不再从运行详情打开；文章属性在侧栏提交。

旧 `final_review/save` 的主编辑稿提交增加可选 `editor: {document_id, revision, text}`，同时提交 `document` 和当前人工待办的 `revision`。服务端要求原文档归属、工作副本精确版本／全文、此前已采用本次运行的文章候选，以及 `document === editor.text` 全部一致，才在原动作事务中同步输出核对基线。请求只授权这一份显式提交的快照，不再次采用候选或写回源文件；后续修改仍会触发原输出保护。不携带 `editor` 的旧客户端保留原行为。

主编辑稿尚未提交时，属性版本提交会禁用并说明下一步；避免把未确认的工作副本变更带入旧输出流程。文章来源返回位于工具栏上方，不悬浮遮挡窄屏审阅内容。

**REVIEW-R02 声明式审阅**：文章与属性待办默认使用主编辑区的当前完整文本，也可在对比后显式选择运行候选正文。确认采用继续携带精确工作副本快照与冲突确认，交由原服务保留历史并更新工作副本。完整 MDX/frontmatter 不在前端重新生成；服务端沿用已知元数据合并和未知字段保护。模拟待办使用独立样例表单，不读写正式文章。

**REVIEW-R03 独立动作**：“采用候选”改变工作副本，“保存文件”写回源文件，“确认输出”写入明确目标，保持独立。历史、revision、磁盘指纹、原子写入与输出效果核验规则不变。本文运行区只展示最近五次历史及完整详情入口；完整时间线在任务页。

**TASK-R01 能力控制**：`NodeDetails`／`HumanAction` 显式接受文章、任务、模拟展示模式。任务模式对候选采用、建议处理、文章确认及旧最终审阅提供“前往文章审阅”，不渲染需要当前正文快照的确认表单。与正文快照无关的追问、脱敏决策、已确认目标输出、停止和恢复核验继续使用原动作协议。

## 工作流与 AI

设计负责流程图、流程级配置与所选节点配置，保留键盘节点选择；测试负责固定样例、模型样例、执行计划／模拟和诊断；版本负责草稿差异、启用、历史和回退。创建／复制位于管理区域；启用只在版本阶段突出。

**AI-UI-R01 分步**：描述目标 → 审阅方案 → 样例测试 → 启用。先明确能力授权，生成结果显式采用到同一流程设计器；再以一至两组固定样例和包含／排除断言验证。表单默认展示，高级 JSON 保留模拟动作和复杂变量。模型分析、修改摘要和不确定性优先，原始定义、权限引用和模拟原始结果放入技术详情。

**AI-UI-R02 验证失效**：设计器修改定义后标记验证失效；保存人工稿，再显式采用并重验。修改本页样例／断言后也禁止使用旧通过结果启用。服务端内容哈希、revision、授权、模型未知请求防重发及关联修复效果保护继续作为最终门禁。

**SETTINGS-R01 生效范围**：应用默认值不会直接更新已有启用流程。流程内模型和目录随版本固定，需明确导入／修改、保存和启用。共享发布配置统一管理，保存新修订不移动节点已固定的修订，节点必须显式重新选择并启用。凭据单独保存，用于后续凭据解析。

## 验证

前端运行 `npm run typecheck` 和 `npm run build`。后端先 `conda activate openai_agents`，核对实际环境后运行 `python -m unittest discover -s tests -v`。浏览器使用临时文章、数据库与模型替身，覆盖导航、刷新、前进后退、会话、待办和候选输出；桌面和窄屏需实际测量溢出并查看截图。实际证据、测试结果与未验证边界记录于根目录唯一的 `implementation-notes.md`。

可复现的浏览器回归在仓库根目录执行：

1. 已有前端构建后，在激活并核对 `openai_agents` 的终端设置 `PYTHONPATH=src`，运行 `python tests/ui_workbench_fixture.py`，保持夹具终端打开。它复用测试中的模型替身，拒绝真实供应商调用，创建临时文章／数据库及服务，写入 `.inkflow/ui-verify/fixture.json`。
2. 使用已有 Playwright／Chromium 运行 `node frontend/tests/workbench.browser.cjs`、`node frontend/tests/workflow-review.browser.cjs` 与 `node frontend/tests/article-tree.browser.cjs`。路径树专项覆盖目录偏好、无扫描、移除与找回、切换失败保护、首次保存／另存为、失联重新关联、搜索与窄屏。默认复用本地已有 `.inkflow/browser-tools/node_modules/playwright`，也可用 `INKFLOW_PLAYWRIGHT_MODULE` 指向现有安装；`INKFLOW_BROWSER_EXECUTABLE` 可指定已有 Chromium。没有这些工具时报告浏览器验证缺口，不自行安装。
3. 脚本拒绝没有 `isolated_ui_fixture` 标记的服务描述，检查唯一导航、切页和刷新、撤销重做、流程草稿、响应式、AI 门禁与修复、任务能力、三个内置流程和声明式输出。证据位于 `.inkflow/ui-verify/`；`INKFLOW_UI_FIXTURE`／`INKFLOW_UI_EVIDENCE` 可指定已有夹具位置和证据目录。
4. 完成后向夹具描述的临时 `root/control.json` 写入 `{"action":"stop"}`，或在夹具终端中断，夹具清理自己的进程和临时数据。不要把测试指向日常工作区或正式服务。

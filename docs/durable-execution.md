# 持久执行与恢复（P4）

正式 Web 运行在服务端推进，关闭浏览器或文章页不会停止执行。服务退出期间不执行；使用相同数据目录、代码与依赖重启后，继续固定的输入与版本。人工待办恢复原身份，不能使用另一篇文章或新的启用版本替换它。CLI 保持原终端执行方式，不恢复中途退出的 CLI；模拟与模型样例重启中断，不修改文档或真实输出。

## 用户可见状态与处理

- **恢复中**：执行器从持久检查点和节点结果继续；等待它回到人工待办或终态。
- **等待输入**：原待办的 run、node、attempt、version、document 与 pending ID 保留。重新打开原文章核对稿件后提交。
- **等待核验**：文件可能已写出，目标缺失、被修改或证据不符。节点详情列出已记录的原目标。“重新核验原目标”只检查同一路径和内容摘要，不能换目标、强制覆盖或补发文件。无法确认时“停止此运行并保留文件”，人工核对后基于当前稿件新建运行。
- **恢复受阻**：协议、实现或检查点不匹配，或模型请求可能已发送但结果没有落库。按提示恢复匹配的代码及依赖，或停止后核对模型调用记录再新建运行；没有自动模型重试。
- **已完成／失败／已停止／已中断**：保留历史。停止不撤销已经写入的文件；旧无恢复协议的运行显示已中断，不猜测位置。

文章在等待或停机期间变化时，旧 revision／正文快照仍被拒绝，`confirm_conflict` 不能绕过版本检查。重新审阅当前稿件后才能明确采用。输出前发现文章确认基线变化会阻止输出，要求停止后重新审阅；当前草稿与历史保留。源文章保存与博客输出始终分离。

## 持久事实与事务边界

**REC-R01 固定执行**：运行创建时固定 `recovery_protocol=1`、核心 Python 源码与 LangGraph／checkpoint 依赖指纹、文档输入、完整版本包、编译计划、提示词和发布配置修订。恢复不读取启用指针。凭据按固定引用重新解析，仅存在内存；模型返回、节点结果与诊断按运行凭据过滤后持久化。

**REC-R02 工作领取**：沿用 RunManager 与四线程执行池。`execution_work` 保存 queued／leased／waiting／blocked／done、命令、停止请求、owner 和 30 秒租约；调度扫描续租并用条件更新领取。数据目录 OS 锁保证同一台机器只有一个执行器；重复领取失败。租约到期本身不证明旧进程停止，不允许强抢活进程。进程退出后 OS 释放锁，新执行器获得锁才释放旧领取。此协议不支持网络文件系统、跨机器 worker 或多服务实例。

**REC-R03 检查点和节点结果**：自有 SQLite saver 实现已安装 LangGraph 的公开同步接口，保存完整 channel 快照与 task writes，使用 `durability="sync"`。节点执行标识由实例、图步数和输入状态摘要组成，节点结果单独持久化；返回后检查点未提交时使用该结果继续。检查点、节点结果和业务事件分别提交；恢复以检查点为执行事实，以节点日志避免重复业务执行，重新投影运行状态。最终输出归档使用已记录的原内容。

**REC-R04 人工动作**：文档更新、前后历史、运行事件、request_id 幂等回执、下一工作记录在同一 SQLite 事务中提交。已接收动作绑定原 checkpoint，不会推进后来的待办。崩溃后重复 request 返回原回执；过期 pending 拒绝。等待态与工作释放在进程锁下推进，文章单活名额保留至明确终态，包括等待核验和恢复受阻。

**REC-R05 模型边界**：调用前保存 started，返回文本落库后才用于后续解析。节点重入时复用已记录返回；started 没有返回证据时受阻，不静默再调用供应商。远端成功与本地回执之间仍有不确定窗口；停止后人工核对再新建可能产生额外费用，不提供供应商端恰好一次语义。正常请求期间的停止等返回／超时后生效。

## 文件效果与对账

**REC-R06 稳定效果**：所有正式图内的博客、审阅稿、Markdown 报告和 JSONL 输出通过公共原子写入边界记录效果。身份绑定 run、节点执行和规范绝对路径；记录内容、SHA-256、原目标摘要和状态：not_started、executing、succeeded、failed、unknown。创建效果前继续使用固定配置、覆盖确认、目标指纹与位置校验；恢复不授权新路径。检查点序列化不使用 pickle。

写入顺序为：保存内容证据 → 标记执行中 → 同目录临时文件写入及 fsync → 原子替换 → 成功回执 → 节点结果 → 图检查点。若在文件写出后崩溃，恢复只读取记录中的原目标：内容摘要一致时确认效果成功，不再写入；缺失或不一致时等待核验。即使停在尚未写出的意图阶段，也保守地要求核验，而非猜测是否替换成功。已确认成功的效果不重复写，即使目标后来被外部修改。可证明尚未到替换阶段的写入错误记录 failed；无法证明的记录 unknown。

对账拒绝原目标及其父路径的符号链接、不读取替代目录；下载使用运行内私有归档。SQLite 和文件系统不是统一事务，**不承诺跨资源恰好一次**：

- 其它进程可在指纹检查与原子替换之间修改目录／文件；当前保护不抵御恶意并发替换。
- 文件内容 fsync 不等于所有平台都保证父目录元数据在断电后持久化；真实测试覆盖进程退出，不代表硬件断电可靠性。
- 节点返回与节点结果提交之间允许重算纯计算；模型通过调用日志、文件通过效果日志防止盲重放。持久结果与事件可能有短暂投影差异，SSE 重连后重读权威状态；事件不是外部效果的成功凭证。
- 崩溃留下的临时文件不自动批量清理，避免误删用户内容。历史、完整检查点、内容证据可能持续增长，当前没有后台压缩或保留期任务。

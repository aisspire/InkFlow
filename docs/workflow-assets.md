# 提示词、流程版本与节点诊断（P2）

## 从工作流入口开始

顶部及文件栏的“工作流”入口不要求打开文章。选择流程，点击模型节点可查看实际 system／user 消息模板、变量声明、默认值、输出协议及模型参数。非模型节点只展示说明；审阅稿、博客和报告节点展示自己的输出配置。

1. 从启用版本或只读历史版本创建草稿。每个流程保留一份服务端草稿；已有草稿不会被覆盖。
2. 修改模板，使用“保存流程草稿”保留内容。保存成功显示“草稿已保存 · 尚未启用”。草稿 revision 在启用、重新创建和刷新后仍不复用；其它页面保存会返回冲突，保留本地内容，可加载最新内容对比后显式合并保存。
3. 填写固定样例变量，点击“本地预览 messages”。这一步只渲染消息，不调用模型。变量仅支持 `{{变量名}}`，不支持表达式、属性访问、代码或文件读取。正文、反馈里的花括号、JSON、Markdown、MDX 都作为数据，一次替换后不再解释。
4. 核对完整消息、模型参数与来源后，点击“发送样例并调用模型”。修改内容后须重新预览。结果保存在私有测试历史，可选记录或节点尝试比较。
5. 保存后点击“启用已保存版本”。校验完整包并在一个 SQLite 事务内生成不可变版本、提示词修订和切换启用指针。校验失败不会改变最近可用版本。

流程、节点及文章间导航保留当前页面内未保存的提示词内容；文章编辑器保持挂载，继续使用 P1 会话。离开浏览器前请保存流程草稿；刷新恢复的是已保存草稿，不承诺恢复未保存的输入或撤销栈。加载／保存期间锁住相关编辑与操作。

## 版本规则

- **ASSET-R01 固定包**：每个注册流程有稳定 ID、不可变版本和启用指针。新运行固定完整包，包含图、输入输出契约、提示词修订、非密钥模型参数、节点实现 SHA-256 和输出配置。人工确认后续跑、复查、追问及重试使用运行固定包，不重新读取当前启用提示词。
- **ASSET-R02 不可变历史**：节点详情的“查看运行提示词与版本”打开只读快照；编辑必须创建草稿。历史版本可比较和回退启用，回退只影响之后创建的新运行，不改写旧记录、不撤销已经写入的文件。
- **ASSET-R03 共享修订**：风险检查与改写被文章处理和仅脱敏共用，但每个流程版本固定自己的修订。界面显示使用该提示词的流程；“查看共享提示词修订”后显式采用、保存、启用才改变当前流程。
- **ASSET-R04 输出协议**：全文检查、风险、改写、文章／追问及兼容 MDX 草稿的原消息已冻结。模板必须保留必要协议字段，输出 schema 和解析器标识不可编辑。风险数组提取、字段归一化、文章 JSON／反斜杠修复及默认值沿用旧行为；这不是新增严格解析器。兼容 `generate_draft` 辅助函数继续使用冻结的初始资产，不增加新内置图。
- **ASSET-R05 配置归属**：`write_review.review` 管理审阅稿，`report.report` 管理报告，`publish.blog` 管理博客目标；审阅时预览博客目标也读取 `publish` 的固定配置。相对路径仍基于原配置目录。`config.toml` 和 `llm.toml` 是初次迁移来源及默认值；修改全局非密钥配置后，需在流程草稿的历史区域点击“把当前全局设置导入草稿”，核对并启用。密钥单独保存，运行创建时按固定 `api_key_env`／本地凭据解析，不写入版本包。
- **ASSET-R06 代码边界**：实现标识包含应用执行源码的 SHA-256；历史版本不保存可执行 Python 环境，不能凭标识重放旧代码。核心代码变化需受控重启；服务检测到源码变动会拒绝创建／启用执行包。重启后从旧版本创建适配当前实现的草稿、核对并启用；不允许把旧实现标识当成新代码执行。没有任意代码热更新。

## 固定样例与诊断

模型试运行使用正式运行的 `WorkflowRuntime.invoke`、模板渲染、LLM 适配器和结果解析函数，仅运行一个模型节点。追问结果只显示，不继续图、更新文档、占正式运行名额或执行审阅稿／报告／博客输出。测试有单独线程池（2 个执行线程，最多 4 个未完成请求），最近 100 条测试可从界面查询；数据库保留更早记录。固定输入和参数用于比较，不保证输出逐字一致。

每次节点执行和模型调用各有尝试 ID，模型调用关联节点尝试，并保存运行／测试 ID、节点 ID、版本、实现标识、时间、耗时、状态、输入、实际消息、模型参数、原始输出、解析结果和分类错误。`previous_attempt_id` 表示前次执行，`retry_of` 仅在前次失败时记录，不提供任意节点恢复。连接、超时、模型格式、业务校验、代码、凭据和停止分别反馈；模型失败的原有文章占位降级仍明确标记，诊断中的模型调用保持失败。

列表不返回输入、messages、原始输出及解析结果；点击具体尝试才加载完整内容，并明确标注未截断、凭据已过滤。过滤作用于诊断副本，不改变业务正文或实际发送给模型的样例。供应商返回 usage 时保存实际值，否则为 `null`。异常与内容过滤当前运行密钥和 Authorization/Bearer 值；这不是通用个人信息脱敏。私有测试和诊断可能含完整文章，应与历史数据库一样保护，普通日志不记录正文或模型输出。

运行诊断沿用 document_id 与运行资源校验，不能指定文件路径；测试诊断校验流程与测试归属。本机同源、Host、请求体上限和 SQLite 数据目录权限继续生效。停止在安全边界执行，已发送的模型请求等待返回或配置超时后结束；停止后不采用模型结果。

## 仅脱敏

`redaction-only` 是独立内置 ID，可从文章工作流选择器或 CLI 选择。实际图为固定原文 → 风险检查 → 逐项审核 → 必要的改写 → 差异确认 → 复查 → 结束。

- 无风险仍等待用户明确确认结束。
- 选择采用／自定义后，复用现有改写与差异。接受候选时校验 document_id、当前 revision 和候选基线，写入工作副本及历史；源文件保持原样，须显式“保存文件”。
- 剩余风险可继续审核处理；全部忽略会明确记录“仍有忽略风险”，不声称无风险。任意等待点可停止；图的递归预算继续限制单次运行。
- 模型关闭或缺密钥拒绝启动；检查请求或格式失败进入 failed，不能当作完成脱敏。
- 不包含文章生成、补充问题、审阅稿、报告或发布节点；原有两个工作流和 CLI 兼容。

## API 与存储边界

| 入口 | 用途 |
| --- | --- |
| `GET /api/workflow-assets/{workflow_id}` | 启用版本、已保存草稿、版本摘要、共享影响和协议 |
| `POST /draft`、`PUT /draft`（同上前缀） | 从指定版本创建草稿；携带 revision 保存完整 package |
| `POST /activate`、`POST /rollback` | revision／generation 校验后启用，或回退指定不可变版本 |
| `GET /versions/{version_id}`、`GET /prompts/{prompt_id}/revisions` | 只读完整版本、提示词不可变修订 |
| `POST /preview`、`POST /tests` | 固定样例本地渲染、显式模型试运行 |
| `GET /tests`、`GET /tests/{test_id}`、`POST /tests/{test_id}/stop` | 测试摘要、完整结果和停止 |
| `GET /tests/{test_id}/attempts[/{attempt_id}]` | 测试尝试摘要／完整内容 |
| `GET /api/runs/{run_id}/attempts[/{attempt_id}]` | 经过原文档资源校验的运行诊断 |

新增 `workflow_versions`、`workflow_heads`、`workflow_drafts`、`prompt_revisions`、`asset_counters`、`node_attempts`、`model_tests`，均在已有私有 `history.sqlite3` 中。启动按缺失流程插入初始资产，可重复执行；不覆盖已有启用指针、草稿、文档、事件、动作幂等和版本关联。完成的 CLI 运行作为无文档关联的只读历史保存，输入和节点诊断仍绑定其流程版本；不编造 document_id。旧运行没有快照时显示“旧版，提示词版本未知”，不填入当前提示词。

升级前停止服务，备份完整应用数据目录、配置与文章；备份 SQLite 时保持服务停止，避免遗漏 WAL。回退旧代码不会理解新资产、测试及诊断；先保存／导出需要保留的新草稿、版本及测试记录，恢复升级前备份，避免新旧程序交替写同库。P1 文档迁移回退边界继续适用。正式 Web 运行由 [P4 持久执行](durable-execution.md) 恢复原待办与固定版本，未知效果先对账；模型样例与模拟仍中断。

P3 已增加[定义驱动编排与发布配置](workflow-definitions.md)，本文继续说明格式 1 内置版本和 P2 兼容路径。P4 持久执行／回执已实施；[P5 来源与自动化](automations.md) 已实施；[P6 AI 编排与修复](ai-orchestration.md) 已实施，复用原版本、诊断与执行服务。

验证入口：[资产与一致性回归](../tests/test_workflow_assets.py)、[P1 回归](../tests/test_documents.py)、[基础回归](../tests/test_regressions.py)。真实模型质量、平台专属权限及浏览器结果须以本轮实际验证记录为准。

# 前端组件与状态

当前页面、URL、能力与会话规则见 [应用导航与文章审阅](../frontend-navigation.md)。全局导航只有文章、工作流、任务、设置；主模块均以页面内容呈现。

- `EditorWorkbench.tsx`：文章会话、持久化草稿、当前工作副本、源码/预览、建议处理、版本、候选冲突对比与主编辑稿回传；按 document_id 保存会话，支持独立文件、未命名稿、首次保存／另存为、失联重新关联与保存反馈。默认保存目录仅预填首次保存位置，校验不登记或扫描工作区。
- `DirectoryField.tsx`：目录手输与原生“浏览…”按钮，管理选择中、取消和错误；用于默认保存目录、另存为与设置，选择只更新字段。
- `api.ts`：同源 JSON 和原生目录选择；保留旧工作区头兼容函数，新资源请求通过明确 ID 定位。
- `OpenArticles.tsx`：所有打开历史按真实路径组成树，压缩单分支目录、区分路径根，未命名稿独立分组；统一搜索、目录方向键、当前文章和草稿／运行／失联状态。移除入口不删除文件，最近文章可重新加入。旧 `WorkspaceExplorer.tsx` 不再挂载到文章页面。
- `SourceEditor.tsx`：CodeMirror 原文、统一标注、UTF-16 范围、正文问题双向选择、按文章缓存 EditorState/滚动/撤销；外部替换作为独立历史步骤。
- `useWorkflow.ts`：按 document_id 选择运行、历史与节点；当前运行 SSE，所有文章摘要轮询，异步响应按文章上下文和 run_id 校验。
- `App.tsx`：本文运行控制、当前待办、辅助流程图与最近五次本文运行摘要；完整详情和时间线进入任务页。
- `navigation.ts`：History API 查询状态与前进／后退订阅，分别保存文章运行与任务选中运行；AI 来源使用会话存储。
- `WorkflowCanvas.tsx`：运行自身真实图与实际执行状态，保留桌面交互、键盘与窄屏列表。
- `NodeDetails.tsx`：逐项脱敏、候选差异、追问、最终文章审核与输出；审核输入按 pending_id 保留，切换窗格或文章不丢失。
- `DocumentDiff.tsx` / `diff.css`：脱敏确认、候选冲突与生成稿载入的共用只读可视化对比；红删绿增、行内标记、行号和统计，支持上下文展开、跳转、放大与并排/逐行布局，窄容器逐行显示。
- `textDiff.ts`：完整文本的有界行匹配与 Unicode 行内匹配，保留行尾与 BOM 差异；大段重写回退完整增删块，界面按需分批渲染。
- `NewRunDialog.tsx`：当前文章工作副本的正式处理运行，不提供无归属的上传/粘贴入口。
- `WorkflowDocumentBridge.tsx`：其它生成稿显式差异对比、候选校验、载入与主编辑稿提交；已确认脱敏稿通过动作直接推进工作副本。
- `MarkdownPreview.tsx`、`SettingsPage.tsx`、`PublishProfiles.tsx`：安全预览、应用默认值／凭据与共享发布配置。文章属性由 NodeDetails 侧栏处理，旧 ArticleEditor 弹窗不再是运行入口。

数据权威：SQLite document_copies 是持久化工作副本；编辑器中的尚未持久化输入由当前文章会话持有。RunManager 记录运行与审核事实，前端建议只是本地编辑映射投影。运行输入、检测快照与候选不得反向覆盖正在输入的正文。历史选择不安装正文，不启用历史修改按钮。

桌面保留浅色三栏；窄屏文件 Drawer 带焦点管理，辅助区纵向排布。隐藏源码预览和折叠窗格不清空编辑状态；切换文章用文档 ID 对应的 EditorState，修改默认保存目录不重挂载正文。刷新恢复路径树、当前文章、默认目录和草稿，显式移除的入口不自动恢复，撤销栈仅限当前页面会话。

## P2 工作流资产界面

WorkflowStudio 从唯一“工作流”全局入口或运行提示词链接进入页面，分为设计、测试、版本，复用 WorkflowCanvas、DocumentDiff 与 MUI；文章编辑器保持挂载。按流程缓存本页未保存的提示词／样例，服务端保存草稿可刷新恢复，保存与启用独立反馈。NodeDiagnostics 按需加载运行／模型测试的尝试详情和比较；非模型节点不显示提示词表单。工作流版本、输出配置与完整错误语义见 [P2 当前行为](../workflow-assets.md)。

## P3 设计器与运行查询

WorkflowStudio 继续保存各流程的本地编辑会话；DefinitionEditor 提供类型目录、节点添加／删除、连接／分支、输入绑定、实例提示词与模型参数、发布配置固定修订选择、计划预览和模拟；共享配置管理归设置页。WorkflowCanvas 展示同一份定义，运行时固定运行包；窄屏保留节点列表与完整表单。NodeDetails 按交互类型复用专用处理器，新增元数据审阅和本地输出确认。RunCenter 位于任务页“运行记录”，复用运行详情、诊断与动作服务；mode=task 将需要文章快照的动作导向原文章审阅，不渲染必定失败的确认按钮。编辑器保持挂载，导航不清除文章编辑状态。

P4 在运行中心、文章运行标签和节点详情共用 recovering／verification_required／recovery_blocked 状态；详情提供重新核验原目标与停止保留文件，错误沿原动作回读链路反馈，不展示租约参数。文章会话与窄屏布局保持。

P5 新增 `AutomationCenter.tsx`，位于任务页“持续关注”，编辑器保持挂载。任务创建、启停、检查、证据、积压和冲突复核可在窄屏访问；候选入口回到原文章和待办，不在自动化页面绕过正文版本保护。

## AI 编排与修复

AIAssistant 由工作流页和失败尝试诊断提供入口，统一在工作流页面按描述目标、审阅方案、样例测试、启用分步显示，复用人工流程定义与编辑器。样例变量和断言默认表单，CaseFields／SampleFields 保留高级 JSON；技术原始数据按需展开。页面独立轮询，返回准确来源并保留结果，历史按文档身份查询；人工修改标记验证失效，采用与验证不会用异步响应覆盖设计器未保存会话。详见 [P6 交互](../ai-orchestration.md)。

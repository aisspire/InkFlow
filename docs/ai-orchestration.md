# AI 编排与修复（P6）

AI 创建、分析和修复沿用 P1–P5 的资产、编译器、模拟、诊断及 RunManager。模型返回结构化建议；服务端检查授权，用户审阅后采用、验证和明确启用。模型不能调用工具、修改源码、历史版本、原运行或效果日志。

## 入口和流程

界面统一位于工作流页，以“描述目标 → 审阅方案 → 样例测试 → 启用”分步呈现；样例和包含／排除断言默认使用表单，高级模式保留 JSON 与明确模拟动作。人工修改会标记验证失效。返回来源和 URL 恢复范围见 [前端交互规则](frontend-navigation.md)。

在“工作流”点击“AI 创建流程”，填写目标、示例输入和输出约束，勾选允许的能力。授权本地博客时须选择已有发布配置修订。点击“发送目标并调用 AI”会使用当前设置中的模型，保存请求所用非密钥参数；模型关闭或无密钥时明确拒绝，不生成伪造分析。

运行记录或文章节点诊断中的失败／中断尝试提供“AI 分析并提出修复”。请求绑定 run_id、node_id、attempt_id、原 workflow_version、实际诊断模型配置、输入摘要、文档及来源快照。即使原流程后来启用新版本，分析仍使用失败尝试的版本。

1. 服务通过已有资产服务创建独立流程身份和草稿；修复复制精确失败版本，P2 内置版本使用既有 P3 迁移规则转成定义。原流程及其启用指针保留。
2. 模型异步返回完整声明式定义和提示词／配置／连接／代码分类、依据、不确定性。保存模型原始响应、usage（未返回则 null）、结构化差异及静态校验诊断。生成中可切页继续编辑；取消只丢弃迟到结果，已发送请求可能计费。
3. 页面优先展示分析、修改摘要和不确定性，生成图用于审阅，节点参数、提示词、权限和结构化差异位于技术详情。无效提案保留错误路径，不能采用。先显式采用有效方案，再打开同一流程设计器人工修改、保存，随后显式采用保存的草稿；不会覆盖未保存的本地编辑。
4. “已核对差异，采用为草稿”核对提案的 revision 和 generation，通过同一资产保存接口写入。版本冲突保留人类稿件；采用人工保存内容同样核对最新版本、重新检查权限并清除旧验证。
5. 填写一至两组固定样例：`name`、`text`、`actions`、`contains`、`excludes`。actions 可显式指定节点、交互类型、动作和参数，也可逐次处理模拟待办；模型调用必须单独勾选允许。
6. 比较原定义和候选定义的模拟。原定义失败可作为修复基线；候选必须完整到达 simulated，并通过全部断言。原／新模拟被停止、中断或等待时不得启用。模拟的文档采用、审阅稿、报告及博客输出使用现有模拟适配器，不写文章或输出目录。
7. “明确启用已验证版本”复用原子版本切换。普通资产启用 API 也检查 AI 草稿的样例门禁，不能用另一个入口绕过失败结果。启用后在设计器保留历史和回退操作；回退只影响之后的运行，不能撤销文件。
8. 修复提案启用后，可以明确使用原文档当前已持久化工作副本创建新运行。运行固定修复版本，`repair_of` 保存原运行、失败节点／尝试、原版本、提案 ID 和新输入摘要。后续仍需人工审阅；没有自动发布。

## 业务规则与权限

- **AI-R01 权限来自请求**：只使用已安装节点及请求明确允许的能力。模型输出中的权限字段、来源文字、样例或诊断不能扩大授权。输出目录只能沿用复制版本已具备的目录；博客引用必须是显式选择或原版本已有的精确修订。新目标在正常配置界面由人创建。
- **AI-R02 连接固定**：模型可调整 temperature、timeout、max_tokens 等已校验参数，不能更换 model、provider、base_url、api_key_env 或 enabled；连接引用来自当前配置／原版本。连接故障可解释原因和提出人工配置建议，不自动读取其它凭据。
- **AI-R03 资料脱密**：发送模型前与保存结果时过滤实际模型密钥、节点密钥、已配置来源凭据和 Authorization/Bearer 字段。文章、样例与诊断依然可能含私人正文，存于私有数据库。这不是通用个人信息匿名化，不承诺识别未知字符串中的所有秘密。
- **AI-R04 不改历史**：提案、比较记录和新版本单独保存。原运行、诊断、效果日志只读。修复默认新流程身份，回退原工作方式也可直接继续选择原流程；不会自动将原自动化任务指向新流程。
- **AI-R05 验证绑定内容**：验证保存样例、明确动作、断言、原／新测试 ID、编译哈希、输出、断言结果、状态和调用授权。完整实际模型参数、消息、用量和耗时位于相应模拟的节点诊断。采用的草稿 revision 与包哈希必须匹配通过记录；编辑后需显式重新采用并重验。
- **AI-R06 不把模型判断当测试**：结构错误由编译器／模板校验定位；样例检查是实际运行状态及节点输出的 contains/excludes 断言。自然语言输出约束只是生成条件，不能代替人工验收或客观断言；通过不代表语义质量证明，也不保证逐字复现。
- **AI-R07 先核验效果**：原运行未终止、处于 recovery_blocked／verification_required、存在成功／意图／未知文件效果或未完成模型效果时，拒绝关联重跑。先按 [P4 核验](durable-execution.md)处理；停止不能抹除未知效果。成功文件即使停止原运行也不自动重放。
- **AI-R08 输入冲突**：关联运行核对原 document_id、当前 revision 和正文。来源必须明确选择原 snapshot_id，并核对保存的来源摘要。首版不复用上游计算结果或成功输出，使用明确输入从头创建新运行；不提供任意节点跳转或产物拼接。
- **AI-R09 代码分开发布**：代码问题仅提供分析。处理步骤是独立源码修改与测试、审阅、按项目发布流程受控重启，之后从旧版本创建适配新实现的草稿。没有脚本执行、动态 import 或 importlib.reload API，现有源码指纹保护继续生效。

## 状态与恢复

提案状态为 generating、ready、invalid、failed、cancelled、interrupted、applied、activated。生成任务最多两个并发，不自动重试模型请求。硬退出后 generating 变为 interrupted，明确结果未知，不重新发送。已采用／启用提案、差异和验证记录保留；进行中的模拟按原 P3 规则中断，不能解释成通过。

界面中的历史提案可重新打开；修复详情和操作继续核对原文档资源身份。文章编辑器保持挂载，AI 页面返回不会清除会话。断网／服务错误显示失败并保留本地输入；返回历史提案时加载已保存事实。

## 接口与数据

所有接口沿用本机同源、Host、请求体限制和数据目录权限，不构成公网多租户服务。

| 入口 | 请求与返回摘要 |
| --- | --- |
| `POST /api/ai/proposals` | 目标、名称、示例、约束、能力、profile_refs、可选 repair_of；返回独立提案及固定草稿 |
| `GET /api/ai/proposals`、`/{id}` | 最近 100 项摘要／完整提案、诊断引用、图、diff、校验与验证；数据库保留更早记录 |
| `POST /api/ai/proposals/{id}/cancel` | 取消生成结果采用；不承诺取消已发送的供应商请求 |
| `POST …/{id}/apply`、`/revise` | revision、generation；采用 AI 内容／已保存人工内容，冲突返回 409 |
| `POST …/{id}/verify` | samples、allow_model；创建原／新模拟并记录实际结果 |
| `POST …/{id}/activate` | 已采用 revision、generation；样例门禁和完整静态校验后启用 |
| `POST …/{id}/runs` | request_id、document_id、revision、text、source_snapshot_id；返回固定版本和 repair_of 的正式运行 |
| 原 `definition-tests/{test_id}/actions`、新增 `/stop` | 完成或停止模拟待办／调用，不推进正式运行 |

仅增量创建 `ai_proposals` 表，不覆盖 P1–P5 数据。提案、模拟、资产版本和运行相互引用；提案采用与草稿保存共用事务，普通启用也在同一版本事务记录 activated_version。模型生成与模拟是独立请求；崩溃可能留下未被提案采用的草稿或测试，不会自动启用。

升级前停服备份整个应用数据目录（SQLite、WAL/SHM、密钥和产物）、配置、源文章及输出。源码变化仍会阻止旧在途执行恢复；先完成／核验旧运行或保留匹配旧源码的环境。回退程序需要匹配旧数据库备份，不交替写同库；数据库回滚不能撤销已经写出的文件。版本回退与程序／数据库回退是不同操作。

## 验证入口

[P6 专项](../tests/test_ai.py)覆盖能力、模板、冲突、脱密、取消、失败门禁、版本绑定及效果防重放；[P6 真实进程回归](../tests/test_ai_recovery.py)覆盖请求发送后退出、验证中断、启用记录和关联修复待办恢复。完整回归仍包括 [P4](../tests/test_recovery.py) 和 [P5](../tests/test_automation.py) 的真实进程边界。

测试和浏览器使用隔离目录、临时文章和模型替身；不把替身通过解释为真实供应商质量或计费验证。实际运行结果和未验证项记录于根目录 implementation-notes.md。

# 定义驱动的流程与本地发布（P3）

P3 在原工作台、版本库和 RunManager 上增加定义编译。三个内置流程继续读取 P2 格式，由原 Python 工厂执行；用户流程由服务端已安装节点目录编译成 LangGraph。保存图描述本身不代表可执行。

## 创建并运行

1. 打开“工作流”，填写新流程名称，创建“发布已有文章”流程；也可复制启用／历史版本为独立身份。复制 P2 流程会生成新的定义草稿并记录来源，不改写旧版本。
2. 在节点目录添加能力，使用节点选择、输入来源、下一节点和分支表单连接；删除节点会删除关联连线，尚未修复的输入绑定会在校验时定位。画布位置单独编辑，不影响执行顺序。
3. 在“设置 → 共享发布配置”创建／管理修订，在工作流设计的“确认本地输出目标”节点选择固定修订。保存共享配置不会更新已有流程。仓库目录必须存在；内容目录为仓库内相对路径。当前只支持 Astro MDX、`<slug>/index.mdx`、逐次确认覆盖或禁止覆盖。
4. 点击“校验并预览执行计划”。校验不调用模型、不修改文档、不写输出文件。修正具体节点、连线或字段错误后，保存草稿，再显式启用。未启用的新流程不能启动；已有流程校验失败时保留原启用版本。
5. 返回文章，选择新流程并启动，无须改源码或重启。输入固定为已登记 `document_id` 的当前工作副本与 revision。填写并确认标题、slug、日期、作者等元数据，审阅正文，再明确确认预览的本地目标。
6. 本地写入成功仅表示对应文件已写入，没有构建、部署、Git 或远程发布。源文章保存仍由“保存文件”负责。

发布已有文章模板为：固定快照 → 文章／元数据准备 → 人工审阅 → 目标确认 → 本地博客 → 结束。不包含模型节点，模型关闭或无密钥仍可执行。正文及首尾空白、Markdown／MDX、JSON 和花括号作为数据保留；正文统一在文章主编辑区修改，属性在右侧审阅。输出时只拼装／更新已确认的元数据；已有 frontmatter 的其它字段与正文保留，不进行模型润色。模板可加入全文检查、脱敏、生成、审阅稿或报告节点。任务详情通过展示能力将文章确认导向原文章，见 [当前审阅规则](frontend-navigation.md)。

P5 增加“来源资料候选”节点与无模型审阅模板，消费自动化固定的证据，详见 [持续关注](automations.md)。

## 类型、定义和编译边界

**DEF-R01 安装边界**：`orchestration/definitions.py` 注册 12 个类型：`snapshot`、`source-material`、`prepare-article`、`review-article`、`confirm-local-output`、`local-blog`、`full-check`、`redaction`、`generate-article`、`write-review`、`write-report`、`end`。每个类型声明版本、可追溯实现标识、输入输出 schema、配置、端口、模型／提示词、交互契约、能力、副作用及预算归属。新增执行代码需安装并受控重启，不接受 Python、JS、shell、动态 import 或表达式。

**DEF-R02 实例隔离**：类型与实例分离，`node_id` 是流程内稳定实例 ID。同一类型可出现多次，输入、提示词修订、模型参数、阶段、节点尝试、候选与待办分别归属实例。提示词经既有受限渲染和解析器处理；编辑不会更换输出协议。模型凭据按实例受控引用在启动时解析，不放入版本、输出或诊断。

**DEF-R03 编译**：外层包格式 `schema_version=2`；内部定义版本 `schema_version=1`；编译协议 `inkflow-plan/1`。编译保存节点实现和类型版本、已解析发布修订、配置、提示词、模型参数、连接、执行预算与计划哈希。运行前再次核对固定编译包，拒绝篡改／不匹配实现。展示图来自同一份定义，运行图不读取当前草稿或最新版本。画布不参与执行哈希。

**DEF-R04 控制流**：顶层为单路受限分支，每个非终点必须有且仅有一个兜底出口，额外分支只能比较源节点声明的布尔或文本值。不接受可执行条件。输入必须绑定类型兼容的已有输出；来源须在每条可能路径上先于消费节点，阻止读取未执行分支。不提供并行扇出／汇合。

没有把全部执行限制成无环图：脱敏、全文建议处理和生成追问是注册的受控子流程，图中显示实例内部循环，正式运行阶段之间使用 P4 持久 checkpoint，模拟仍使用内存 checkpoint。脱敏支持审核、改写、差异、复查，生成复用最多三次追问规则。每个实例有 `max_iterations`，整图另有 `max_steps`；停止和预算失败有明确出口。任意顶层回边被拒绝，不能绕过循环预算。

**DEF-R05 校验**：重复 ID、未知类型／版本、非法配置、未知端口／字段、类型不兼容、不支配绑定、不可达节点、缺入口／终点、分支无兜底、任意循环、缺提示词／发布修订／能力都会阻止启用。发布必须消费确认节点的 `publication`，确认节点必须消费人工审阅产生的 `reviewed-article`；普通正文或任意常量不能伪造确认产物。

**DEF-R06 草稿与版本**：结构完整但业务校验失败的定义可保存为草稿，激活时必须完整编译。revision 使用原持久单调计数器，删除重建不复用；启用和回退校验 generation。流程名称在定义中修改，稳定 ID 与旧运行归属不变。页面内切换文章、流程和节点保留未保存定义、配置和提示词；刷新恢复已保存内容，未保存内容不承诺跨刷新恢复。

## 交互、文档与输出

待办包含 run、workflow、version、node、attempt、document、pending ID、交互类型和动作契约。`suggestion_review`、`redaction_review`、`diff_review`、`article_question` 复用原处理器；`article_metadata` 和 `local_output` 提供文章表单与目标确认。服务端检验动作和 payload，不能靠隐藏按钮绕过。过期 pending、重复 request 与同文档活跃运行互斥继续生效。

**DEF-R07 文章确认**：正式文章确认必须携带 editor `{document_id, revision, text}`，服务端在同一文档锁内核对当前版本与正文，再采用审阅稿。缺失快照拒绝；文档不符、版本过期或正文基线不符时保留当前草稿与待办，要求重新打开文章并审阅。显式 `confirm_conflict` 只允许在核对最新快照后替换与运行输入不同的草稿，不能绕过版本保护。模拟没有文档，不要求 editor。

建议采用和脱敏确认通过 DocumentService 校验文档 ID、revision、输入／候选基线与冲突确认，更新工作副本并保留历史，不写原文件。流程后续节点读取固定产物；全文建议结束时服务端固定已确认的工作副本，脱敏后传递明确接受的候选。普通文章结果仍通过“对比并载入编辑区”采用，历史运行只读。

**PUB-R01 固定修订**：PublishProfile 有稳定 ID、generation 和不可变 revision。编辑共享配置会产生新修订并展示当前启用版本引用，只有显式采用到流程草稿、保存和启用后才影响新运行。运行中的配置不会变化。配置只含非密钥目标、真实支持的格式、命名和覆盖策略。

**PUB-R02 目标保护**：实际预览与写入消费同一份配置、文章和目标快照；覆盖要求明确确认，写前复验路径、存在状态与 SHA-256。非法 slug、内容目录越界、内容目录／目标的符号链接和权限失败均拒绝写入。复用现有进程锁和原子写入；不承诺抵御其它进程恶意竞争替换目录。

审阅稿、报告和博客是独立节点能力；产物归档附 `node_id`，多个同类输出不会相互覆盖归档标识。本次没有工作区默认流程、配置覆盖或任意运行参数覆盖；运行时页面切换不改变目录。P2 全局 TOML 仍为兼容来源和显式导入默认值，原目录不自动重定向。

## 预览、试运行与诊断

- 静态计划预览只校验和解析定义，不调用模型、不写文档和输出。
- 单模型样例沿用 P2 服务，可按节点实例及提示词选择；本地 messages 预览与显式调用分开，记录固定输入、参数、修订和真实响应。
- 流程模拟使用相同编译器、绑定、分支、渲染、结果校验和图执行器。文档采用、审阅稿、报告和博客输出在能力边界模拟；目标模拟甚至不读取正式目标目录。结果明确为 `simulated`，不报告真实发布成功。
- 模拟有独立身份、线程池、历史和待办，不占正式文档名额。模型节点必须显式允许调用；人工节点逐次交互，或提供明确绑定节点／交互类型的样例动作，不能默认批准正式发布。模拟建议仅查看或结束，正式建议采用需原文章快照。
- 试运行记录含固定输入、定义来源、计划版本、节点尝试、模拟路径、结果和错误，可选两次记录比较。诊断的凭据过滤仅用于副本；不预先改写送给模型的业务数据。

“运行记录”入口列出已登记文档范围的运行，按状态、流程、文档和明确工作区范围筛选。详情显示运行自己的定义，可进入待办、诊断或原文章。与文章侧栏共用 RunManager、HistoryStore、动作与 SSE；没有另建正式执行系统。候选采用需要文档快照时从运行中心返回原文章操作。

| `GET /api/node-types`、`/{type_id}/instance` | 已安装目录、schema、契约、默认实例 |

## 迁移、备份与回退

升级前停止服务，备份整个应用数据目录（含 SQLite 及可能存在的 WAL／SHM）、配置、文章和输出文件。旧 P2 包格式 1 保留原事实；创建可编辑定义时产生新身份草稿、记录原 workflow/version，并复制固定提示词和有效输出路径。原内置流程和 CLI 保持兼容。用户定义目前从 Web 启动；CLI 的可选 ID 仍为三个内置流程。

源码指纹是实现身份核对，不提供旧代码执行环境。旧包与当前安装实现不兼容时拒绝执行，需显式创建／启用新草稿；不能偷偷替换实现。P2 → P3 复制是明示迁移，人工确认分层和默认终止策略请在计划预览、试运行中核对。

流程版本回退只改变启用指针，影响之后创建的运行；不会回退数据库、工作副本或已经写出的博客文件。回退旧代码前先保存／导出新草稿和记录，再按需要恢复升级前数据库备份；不要让新旧代码交替写同一数据库。

[P4 持久执行与对账](durable-execution.md) 已实施。正式运行恢复原待办、版本与发布修订，已确认成功的输出不重写；模拟重启仍中断。[P5 来源采集、计划、变化检测和自动化](automations.md) 已实施；[P6 AI 编排与修复](ai-orchestration.md) 已实施，复用原版本、诊断与执行服务。

验证入口：[P3 定义与执行回归](../tests/test_orchestration.py)、[P2](../tests/test_workflow_assets.py)、[P1](../tests/test_documents.py)、[基础／CLI／SSE](../tests/test_regressions.py)。具体本轮结果、浏览器证据及未验证项记录于根目录 `implementation-notes.md`，不把模型替身当成真实模型验证。
